1. **Environment** of its development and use — intended users, application area, popular software-engineering approach at the time, the computers it targeted.
2. **How that environment affected the language.**
3. Its **main contribution(s)**.

## Fortran — scientific computing, compiled for speed
**Environment:** IBM 704 — little memory, slow, unreliable, but it had **index registers and floating-point hardware**. Applications were **scientific and fairly simple**. No programming methodology or tools; **machine efficiency** was the main concern.

**Effect on the language:**

- Floating point and indexing were now in hardware, so there was nowhere to hide the cost of interpretation → the idea of a **compiled** language. Compiled programs **had to be fast**.
- No need for dynamic storage; needed good **array handling and counting loops**.
- **No string handling, decimal arithmetic or powerful I/O** (only needed for business software).

**Fortran I features:** names up to 6 characters, post-test counting `DO` loop, formatted I/O, user subprograms, **three-way (arithmetic) IF**, **no type declarations** (names starting with I–N were integers, others floating point). Programs over ~400 lines rarely compiled (unreliable 704, no separate compilation) → **Fortran II** added **independent compilation**.

Later: Fortran IV (explicit types, logical IF, subprogram names as parameters), 77 (strings, IF-THEN-ELSE), 90 (modules, dynamic arrays, pointers, recursion, CASE, parameter type checking), 2003 (OOP), 2008 (co-arrays, DO CONCURRENT).

**Evaluation / contribution:** **highly optimised compilers** (pre-90: all types and storage fixed before run time, no recursion); it **changed forever how computers are used** — the *lingua franca* of computing.

## LISP, Scheme and Common LISP — functional programming
**LISP environment:** **AI research** needed a language for processing data in **lists** (not arrays), **symbolic** (not numeric) computation, **recursion**, and **automatic dynamic storage** handling.

**Effect:** only two data types — **atoms and lists**; syntax based on **lambda calculus**; no variables or assignment needed; control via recursion and conditional expressions.

**Contribution:** **pioneered functional programming**; still used in AI.

**Scheme** (MIT, mid-1970s): small language, simple syntax → **ideal for education**; **exclusively static scoping**; **functions as first-class entities** (passed as parameters and returned as results).

**Common LISP:** feature-rich, combines several LISP dialects — "the opposite of Scheme": large and complex, **both static and dynamic scoping**, many data types; used for some large industrial applications.

## ALGOL 58 / ALGOL 60 — the first step toward sophistication
**Environment:** Fortran had barely arrived (only for IBM); many other languages existed, **all for specific machines** — **no portable language** and no universal way to communicate algorithms. An international effort aimed at a **machine-independent**, universal language (still scientific): close to mathematical notation, good for describing algorithms, translatable to machine code.

**ALGOL 58** formalised the concept of **type**, allowed names of any length, arrays with any number of subscripts (and programmer-set lower bounds), compound statements (`begin … end`), `:=` assignment, nested `if` with else-if — and **no I/O** ("would make it machine dependent"). Not meant to be implemented; IBM dropped support.

**ALGOL 60 added:** **block structure** (local scope), **pass by value and pass by name**, **recursion** (first imperative language with it), **stack-dynamic arrays** (size set at run time). Still no I/O or strings.

**Successes:** the standard way to **publish algorithms** for 20+ years; basis of **all later imperative languages**; first **machine-independent** language; first with **formally defined syntax (BNF)**.

**Failures:** never widely used (especially in the US) — lack of I/O (ironically making programs non-portable), **too flexible** (hard to understand and implement), BNF confusing at the time, Fortran entrenched and **no IBM support**.

## COBOL — business records
**Environment:** only a few proprietary business languages (FLOW-MATIC, AIMACO, COMTRAN); the US DoD wanted a common business language. Goals: **look like simple English**, **easy to use even at the cost of power**, **broaden the base of computer users**, not be biased by compiler problems.

**Contributions:** **hierarchical data structures (records)**, **nested selection statements**, **long names (up to 30 characters) with hyphens**, a separate, very detailed **data division**; still widely used for business applications.

**Drawbacks:** weak **procedure division** (every statement starts with a verb, English names for arithmetic), initially **no subprograms with parameters**.

## BASIC — timesharing
**Environment:** designed at Dartmouth for **non-science students**: easy to learn and use, "pleasant and friendly", **fast turnaround** for homework, free and private access — **user time more important than computer time**.

**Contribution:** the **first widely used language with timesharing**. Modern dialects: Visual BASIC, VB.NET.

## PL/I — everything for everybody
**Environment (IBM's view, 1963):** scientific users (Fortran) wanted COBOL-like I/O; business users wanted floating point and arrays. Organisations were paying for **two kinds of computers, languages and support staff**. Solution: one computer line (System/360) and **one language for both** — plus systems programming and list processing.

**Contributions (firsts):** **unit-level concurrency**, **exception handling**, switch-selectable **recursion**, **pointer data type**, **array cross sections**.

**Concerns:** many new features were **poorly designed**; **too large and complex** — it tried to include every available construct and many data structures.

## APL — an early dynamic language
**Environment:** designed at IBM, initially as a **hardware description** language.

**Characteristics:** **dynamic typing** (a variable gets a type when assigned; type can change) and **dynamic storage allocation**. **Highly expressive** — a very large number of operators that work on scalars and arrays (powerful array operations).

**Evaluation:** programs are **very difficult to read** (the classic writability-vs-readability example). Still used with minimal changes.

## SIMULA 67 — the beginning of data abstraction
**Environment:** designed in Norway primarily for **system simulation**; based on ALGOL 60 and SIMULA I.

**Contributions:**

- **Coroutines** — subprograms that **restart where they previously stopped** (needed for simulation).
- **Classes and objects** — the **beginnings of data abstraction** (not full OOP).

## ALGOL 68 — orthogonal design
Continued from ALGOL 60 but very different. **Design based on orthogonality** — a few basic concepts and combining mechanisms, allowing **user-defined data structures** (contrast PL/I, which tried to provide every data structure directly).

**Contributions:** user-defined data structures, **reference types**, implicit heap-dynamic **flex arrays**.

**Comments:** less used than ALGOL 60 and PL/I; **too orthogonal** in some ways; described in an unknown meta-language (Van Wijngaarden grammar); strong influence on **Pascal, C and Ada**.

## ALGOL descendants: Pascal and C
**Pascal:** small, simple, **nothing really new**; designed for **teaching structured programming** — the most widely used teaching language from the mid-1970s to the late 1990s.

**C:** designed for **systems programming** (Bell Labs), evolved from CPL, BCPL, B and ALGOL 68. Powerful set of operators, but **poor type checking** and other unsafe features. Spread through **UNIX**; used in many areas.

## Prolog — programming based on logic
**Environment:** natural language processing (Aix-Marseille) and automated theorem proving (Edinburgh).

**Overview:** based on **formal logic**, **non-procedural** — a database of facts and rules plus a built-in **inferencing** process. **Highly inefficient**, with few application areas.

## Ada — history's largest design effort
**Environment:** the US DoD had **450+ languages** in use on its projects and needed **one standard** language, initially for **embedded systems**. Huge competitive design effort (hundreds of people, lots of money, ~8 years).

**Contributions:** **packages** (data abstraction), **elaborate exception handling**, **generic program units**, **concurrency** (tasking and the rendezvous model).

**Comments:** included **everything known about software engineering and language design** at the time; usable compilers took nearly five years.

## Smalltalk and C++ — object-oriented programming
**Smalltalk** (Xerox PARC): **first full implementation of true OOP** — data abstraction, inheritance, **dynamic binding**; pioneered **graphical user interface** design and promoted OOP.

**C++:** from **C and SIMULA 67**; large and complex — procedural plus OOP, exception handling, operator overloading, pointers, references, templates, classes. Popular because of **good cheap compilers**, **backward compatibility with C**, and being the **only OO language then suitable for large projects**. Related: Swift (Apple's Objective-C replacement), Delphi (Pascal + OOP, safer than C++), Go (Google; OO *style* without traditional OOP).

## Java and C# — modern imperative OO
**Java environment:** initially for **embedded consumer electronics**, where C and C++ were too **unreliable**.

**Effect:** based on C++ but **simplified and more reliable** — removes `struct`, `union`, `enum`; **no pointers or pointer arithmetic (references only)**; about half of C++'s assignment coercions; **OOP only**; supports applets, concurrency, GUIs.

**Evaluation:** eliminated many unsafe C++ features (so less powerful/flexible than C++); large libraries; **portable** via the JVM and JIT compilers; widely used for web programming.

**C#** (part of .NET): based on C++, Java and Delphi; added pointers, delegates, properties, enumerations, limited dynamic typing, anonymous types; supports **component-based development** — common type system and class library across .NET languages, all compiled to **Intermediate Language** with a **JIT** compiler.

## Scripting languages and markup hybrids
Scripting languages are imperative but: meant for **smaller tasks**, usually **interpreted**, and mostly **dynamic** constructs.

- **Perl:** UNIX text processing, later CGI and system administration. Variables statically typed but **implicitly declared** by their first character (`$` scalar, `@` array, `%` hash). Powerful but dangerous: dynamic-length sparse arrays, string↔number coercions, no array-access error detection.
- **PHP:** server-side, **HTML-embedded**, form processing and database access via the web; purely interpreted.
- **JavaScript:** client-side, HTML-embedded, dynamic HTML; purely interpreted; related to Java only by syntax.
- **Python:** OO interpreted scripting (CGI, forms, admin, data science); type checked but **dynamically typed**; lists, tuples, hashes; huge library ecosystem.
- **Ruby:** started as a Perl/Python replacement; **purely OO** — all data are objects, most operators are methods that **user code can redefine**; classes and objects are dynamic.

**Markup/programming hybrids** — **XSLT and JSP**: markup languages (document structure) extended with programming features such as loops, `if` blocks and sorting.

# Traps
- You don't need dates, version numbers, machine models or designer names — focus on **environment → effect → contribution**.
- Fortran I was compiled because the 704 had **floating-point and index hardware** (no place to hide interpretation cost).
- ALGOL 60's lack of I/O **made programs non-portable** (ironic, since I/O was left out for machine independence).
- SIMULA 67 = coroutines + beginnings of data abstraction (**not** full OOP). Smalltalk = first **full** OOP.
- PL/I = "everything for everybody": many firsts, but too large and complex.
- ALGOL 68 = orthogonality (too much); PL/I = provide everything directly.
- Java has references only, no pointers; C# has both (pointers only in `unsafe` code).
- Perl variables are statically typed but **implicitly declared** (by `$ @ %`).

# Flashcards
Q: Why was Fortran I compiled rather than interpreted?
A: The IBM 704 had floating-point and index hardware, so interpretation's cost could no longer be hidden; programs had to be fast.

Q: What did Fortran I leave out and why?
A: Strings, decimal arithmetic, powerful I/O, dynamic storage — not needed for simple scientific applications on the 704.

Q: LISP's environment and contribution?
A: AI research needing list processing, symbolic computation, recursion, automatic dynamic storage. Pioneered functional programming.

Q: ALGOL 60's main successes?
A: Algorithm publishing standard, basis for later imperative languages, first machine-independent language, first formal syntax (BNF), block structure, recursion.

Q: Why did ALGOL 60 fail to be widely used?
A: No I/O, too flexible to implement/understand, BNF seemed confusing, Fortran entrenched, no IBM support.

Q: COBOL's contributions?
A: Hierarchical records, nested selection, long hyphenated names, separate data division.

Q: BASIC's main contribution?
A: First widely used language with timesharing; easy for non-science students.

Q: PL/I firsts?
A: Unit-level concurrency, exception handling, switch-selectable recursion, pointer type, array cross sections.

Q: SIMULA 67's contributions?
A: Coroutines and classes/objects — the beginnings of data abstraction.

Q: ALGOL 68's design philosophy and contributions?
A: Orthogonality; user-defined data structures, reference types, flex arrays.

Q: Ada's contributions?
A: Packages, elaborate exception handling, generic units, tasking/rendezvous concurrency.

Q: Why was Java created and how did that shape it?
A: Embedded devices needed reliability C/C++ lacked → simplified C++, no pointers, fewer coercions, OOP only.

Q: Smalltalk's contribution?
A: First full implementation of OOP (data abstraction, inheritance, dynamic binding); pioneered GUIs.

Q: How are Perl variables typed?
A: Statically typed but implicitly declared by their first character: $ scalar, @ array, % hash.
