# Notes

## What logic programming is
Logic programming languages (also called **declarative** languages) express programs in **symbolic logic** and produce results with a **logical inferencing** process.

- **Declarative, not procedural:** you specify the **form of the result**, not the step-by-step procedure for producing it.
- **Declarative semantics:** each statement's meaning can be determined simply and is **context-independent** → logic-language semantics are simpler than imperative semantics.
- Programs use **predicate calculus** (the description mechanism) and **resolution** (the inference process).

Sorting example — imperative: describe a sorting *algorithm*. Logic: describe what a sorted list *is*:

```
sort(old, new) ⊂ permute(old, new) ∩ sorted(new)
sorted(list) ⊂ ∀j such that 1 ≤ j < n, list(j) ≤ list(j+1)
```

## Predicate calculus: propositions
A **proposition** is a logical statement that may or may not be true. It consists of **objects** and **relationships** among them.

**Symbolic logic** meets the three basic needs of formal logic: **express propositions**, **express relationships between propositions**, and **describe how new propositions can be inferred** from others. Logic programming uses **first-order predicate calculus**.

**Simple terms** (represent objects):

- **Constant** — a symbol for one particular object.
- **Variable** — a symbol that can represent different objects at different times (not like an imperative variable — there is no memory cell being updated).

**Atomic propositions** are written like a function: a **functor** (names the relationship) + an **ordered list of parameters** (a tuple):

```
student(jon).          like(seth, osx).       like(nick, windows).
```

A proposition can be stated as a **fact** (assumed true: "Jon is a student") or a **query** (truth to be determined: "can you prove Jon is a student?").

**Compound propositions** join two or more atomic propositions with logical operators:

| Name | Symbol | Meaning |
|---|---|---|
| negation | ¬a | not a |
| conjunction | a ∩ b | a and b |
| disjunction | a ∪ b | a or b |
| equivalence | a ≡ b | a is equivalent to b |
| implication | a ⊃ b / a ⊂ b | a implies b / b implies a |

## Horn clauses, resolution and unification
Logic programs use a restricted form of propositions — **Horn clauses** — which can represent most propositions. Only two forms:

- **Headed:** one atomic proposition on the left (**consequent**), a conjunction on the right (**antecedent**). Used for **rules**: `likes(bob, trout) ⊂ likes(bob, fish) ∩ fish(trout)`.
- **Headless:** empty left side. Used for **facts** and **queries**: `father(bob, jake)`.

**Resolution** is an inference principle that computes inferred propositions from given ones — a **matching** process:

```
older(joanna, jake) ⊂ mother(joanna, jake)
wiser(joanna, jake) ⊂ older(joanna, jake)
∴ wiser(joanna, jake) ⊂ mother(joanna, jake)
```

**Unification** finds values for variables that let matching succeed. A variable is **instantiated** with a temporary value; if matching later fails, Prolog **backtracks** and instantiates it with a different value.

Resolution can **prove theorems**: **hypotheses** = the set of assumed propositions (facts and rules); **theorem** = the new proposition (query) we want to infer.

## Prolog terms and statements
Prolog was developed in the early 1970s (Aix-Marseille: natural language processing; Edinburgh: automated theorem proving). We use **Edinburgh syntax**.

**Terms**

- **Constant:** an **atom** or an integer. An atom is a symbolic value: a string of letters/digits/underscores **starting with a lowercase letter** (`joe`) or any characters in apostrophes (`'Some Atom'`).
- **Variable:** letters/digits/underscores **starting with an uppercase letter** (`X`, `MyVar`). **Instantiation** (binding a variable to a value) **only happens during resolution**.
- **Structure:** represents an atomic proposition: `functor(param1, param2, ...)`.

**Three kinds of statements**

```prolog
% Facts — headless Horn clauses (hypotheses)
female(shelley).
father(bill, jake).

% Rules — headed Horn clauses: consequent :- antecedent
% Commas in the antecedent are implied ANDs; the consequent is a single term.
parent(X, Y) :- mother(X, Y).
parent(X, Y) :- father(X, Y).
grandparent(X, Z) :- parent(X, Y), parent(Y, Z).

% Goals (queries) — the theorem Prolog must try to prove
?- father(bill, jake).
?- parent(X, mike), male(X).    % conjunctive goal made of subgoals
```

Variables in rules are **universal objects**: `parent(X, Y) :- mother(X, Y).` holds for all X and Y. **OR** is expressed by writing **several rules with the same head**.

## The Prolog inferencing process
To prove a goal Q, Prolog must find a **chain** of facts and rules linking Q to facts (`B :- A`, `C :- B`, …, `Q :- P`). This is **matching**; proving a subgoal is **satisfying** it.

**Bottom-up resolution (forward chaining):** start with facts and rules, look for a sequence of matches leading to the goal — works well with a **large** set of possibly correct answers.

**Top-down resolution (backward chaining):** start with the goal, look for a sequence of matches leading to facts — works well with a **small** set of possible answers. **Prolog uses top-down.**

<!-- diagram:chaining -->

With several subgoals Prolog could search **breadth-first** (all subgoals in parallel) or **depth-first** (find a complete proof of the first subgoal before working on the second). **Prolog uses depth-first** — it needs fewer computational resources.

**Backtracking:** when a subgoal fails, Prolog goes back to the **previous** subgoal and looks for a different solution, **starting where the previous search left off**. It can take a lot of time and space.

```prolog
?- male(X), parent(X, shelley).
```

Prolog finds a male, then checks if he's Shelley's parent; if not, it backtracks to the next male. It's suboptimal because it may try *every* male — swapping the subgoals (`parent(X, shelley), male(X)`) tries only Shelley's parents.

## Tracing: call, exit, redo, fail
Prolog's built-in `trace` shows instantiations with **four events**:

- **Call** — start of an attempt to satisfy a goal.
- **Exit** — the goal has been satisfied.
- **Redo** — backtracking back into the goal.
- **Fail** — the goal fails.

```prolog
likes(jake, chocolate).   likes(jake, apricots).
likes(darcie, licorice).  likes(darcie, apricots).

?- likes(jake, X), likes(darcie, X).
(1) Call: likes(jake, _0)?       (1) Exit: likes(jake, chocolate)
(2) Call: likes(darcie, chocolate)?  (2) Fail: likes(darcie, chocolate)
(1) Redo: likes(jake, _0)?       (1) Exit: likes(jake, apricots)
(3) Call: likes(darcie, apricots)?   (3) Exit: likes(darcie, apricots)
X = apricots
```

## Arithmetic: the is operator
Prolog has integer variables and arithmetic, evaluated with **`is`**:

```prolog
A is B / 17 + C.
```

- Right operand: an arithmetic expression — **all its variables must already be instantiated**.
- Left operand: a variable that must **not** be instantiated yet; it becomes instantiated with the value.
- It is **not assignment**: `Sum is Sum + Number.` is **illegal** (Sum can't be both instantiated and uninstantiated).

```prolog
speed(chevy, 105).   time(chevy, 21).
distance(X, Y) :- speed(X, Speed), time(X, Time), Y is Speed * Time.
?- distance(chevy, X).        % X = 2205
```

**Comparisons** can be used as terms (subgoals): `=` (unification — not assignment), `<`, `>`, `=<` (note the spelling), `>=`.

```prolog
lessThan(X, Y) :- X < Y.
```

## Lists in Prolog
Lists are the second basic data structure: a sequence of any number of atoms, atomic propositions or other lists.

| List | Meaning |
|---|---|
| `[apple, prune, grape]` | simple list |
| `[[a, b], son(X, bob)]` | complex list |
| `[]` | empty list |
| `[X]` | one element X |
| `[X \| Y]` | head X, tail Y |
| `[X1, X2 \| Y]` | first two elements, then tail Y |

**Writing list propositions** — same recursive strategy as Scheme, but:

- there is **no return** — the result is an extra **parameter**;
- base and recursive cases are **separate statements** (base cases are often facts with variables; recursive cases are rules);
- you **don't** write the negative (false) cases;
- **order matters** — Prolog matches top to bottom, so put base cases **first** (this means Prolog isn't entirely context-independent);
- `_` is the **anonymous variable** — "I don't care what this unifies with".

```prolog
member(Element, [Element | _]).
member(Element, [_ | Lis]) :- member(Element, Lis).

append([], Lis, Lis).
append([Head | Lis_1], Lis_2, [Head | Lis_3]) :- append(Lis_1, Lis_2, Lis_3).

reverse([], []).
reverse([Head | Tail], List) :- reverse(Tail, Result), append(Result, [Head], List).
```

All of these work with variables in **any** position: `append(X, [c, d], [a, b, c, d])` gives `X = [a, b]`.

## Deficiencies of Prolog
1. **Resolution order control** — Prolog always matches facts/rules **top to bottom** and subgoals **left to right**. The programmer affects efficiency (e.g. put rules more likely to succeed first, order subgoals well, use **cuts** `!` to stop backtracking) — but then the program is no longer purely declarative.
2. **The closed-world assumption** — Prolog can only prove what its facts and rules allow. "true" = provable; **"false" = cannot be proven**, not necessarily false. You get a false answer for a true statement if facts are missing.
3. **The negation problem** — `not` is not logical NOT. `not(G)` succeeds if `G` **fails**, i.e. can't be proven.

   ```prolog
   parent(bill, jake).  parent(bill, shelley).
   sibling(X, Y) :- parent(M, X), parent(M, Y).
   ?- sibling(X, Y).   % X = jake, Y = jake  (!)
   sibling(X, Y) :- parent(M, X), parent(M, Y), not(X = Y).
   ```

   `not(X = Y)` means resolution **can't prove** X and Y are the same — not that they are different. Properly proving two atoms unequal would need a fact for every pair (impractical).
4. **Intrinsic limitations** — some tasks can't be specified efficiently. Sorting by "a permutation that is sorted" literally generates permutations until one is sorted — hopelessly slow.

## Implementation rules for tests and exams
- SWI-Prolog under Windows; documentation and the Practical 3/4 specs are available, but you're expected to write code largely without them.
- Allowed: simple constants, variables, list manipulation, arithmetic & relational expressions, `is`, **cuts**, and the built-in **`not`**.
- **Not allowed:** if-then / if-then-else (`->`), the `;` "or" operator, `|` outside a list, and **any** built-in predicates — including `member`, `append`, `reverse`, `abs`. Write your own.
- Test with **variables** and **re-query** (`;` or `r`) to check no invalid instantiations appear.

> Guard every recursive rule (`H > 0`, `H = 0`, `H < 0`, `not(H = X)`) so that each element can match exactly one rule. That's what stops wrong answers on re-query.

# Brief
**Declarative**: state the form of the result, not the procedure. Semantics are context-independent → simpler than imperative.

**Predicate calculus**: proposition = objects + relationships. Terms: constants, variables. Atomic proposition = functor + parameter tuple. Fact (assumed true) vs query (to prove). Compound = atomic props + ¬ ∩ ∪ ≡ ⊃.

**Horn clauses**: headed (rule: consequent ⊂ antecedent) or headless (fact/query).
**Resolution** = infer new propositions by matching. **Unification** = find variable values that make matching succeed; **backtrack** on failure.

**Prolog**: atoms lowercase, variables Uppercase, structures `f(a, b)`. Facts, rules (`:-`, commas = AND, multiple rules = OR), goals (`?-`).
Inference: **top-down / backward chaining**, **depth-first**, **backtracking**. Trace events: Call, Exit, Redo, Fail.

**is**: RHS fully instantiated, LHS uninstantiated; not assignment (`X is X + 1` illegal). Comparisons `= < > =< >=`.

**Lists**: `[H|T]`, `[X, Y|T]`, `[]`, `_`. Result is a parameter; base cases first; no false cases.

**Deficiencies**: resolution order control, closed-world assumption, negation problem (`not` = not provable), intrinsic limitations (permutation sort).

# Traps
- "false" in Prolog means **cannot be proven** (closed-world assumption), not "definitely false".
- `not(X = Y)` succeeds when X and Y **can't be unified** — it is not a true logical NOT.
- `X = Y + 1` does **not** compute anything; it unifies X with the structure `+(Y, 1)`. Use `is`.
- `Sum is Sum + N` is illegal — a variable can't be re-instantiated.
- `<=` is not Prolog — less-than-or-equal is `=<`.
- Prolog uses **top-down (backward chaining)** and **depth-first** search, not bottom-up/breadth-first.
- Order of rules matters (top to bottom) — base cases first — so Prolog isn't fully context-independent.
- Without guards, re-querying produces extra wrong answers; built-in `member/append/reverse/abs` are banned in tests.
- Lowercase names are atoms: `newtail` is a constant, not a variable.

# Flashcards
Q: Why are logic languages called declarative?
A: Programs specify the form of the result, not the procedure to compute it; statement meaning is context-independent.

Q: What are the two forms of Horn clause and what is each used for?
A: Headed (single atomic consequent, conjunction antecedent) → rules. Headless (empty left side) → facts and queries.

Q: Resolution vs unification?
A: Resolution: inference rule that derives new propositions by matching. Unification: finding variable values that let matching succeed.

Q: Top-down vs bottom-up resolution — which does Prolog use and when is each good?
A: Prolog: top-down (backward chaining), good for a small set of candidate answers. Bottom-up (forward chaining) suits large sets.

Q: Depth-first vs breadth-first subgoal search?
A: Depth-first proves the first subgoal fully before the next (Prolog — fewer resources). Breadth-first works on all subgoals in parallel.

Q: The four trace events?
A: Call, Exit, Redo (backtracking), Fail.

Q: Rules for the is operator?
A: RHS: arithmetic expression with all variables instantiated. LHS: an uninstantiated variable. Not assignment.

Q: What is the closed-world assumption?
A: Prolog only knows its facts and rules: "false" means the query can't be proven, not that it is false.

Q: What is the negation problem?
A: not(G) succeeds if G can't be proven — not a logical NOT. not(X = Y) doesn't prove X and Y differ.

Q: The four deficiencies of Prolog?
A: Resolution order control, closed-world assumption, negation problem, intrinsic limitations.

Q: What does the anonymous variable _ mean?
A: A value we don't care about — unification can bind it to anything; it isn't used to define the result.

Q: How is OR expressed in Prolog without ;?
A: Write several rules with the same head — Prolog tries each in turn.

Q: Why must base cases come first in Prolog list propositions?
A: Prolog matches statements top to bottom; base cases should be matched first.

Q: Why is ?- male(X), parent(X, shelley). suboptimal?
A: It tries every male and backtracks; parent(X, shelley) first restricts X to Shelley's parents.
