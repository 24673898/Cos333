### ch05-q1 | mcq | 2026 Exam Q5
```
func()
  myValue.allocate(2)
  myValue[0] = 12
  myValue[1] = 10
  print(myValue[0] + myValue[10])
  deallocate(myValue)
```
`myValue` is an array allocated for two integers. Which variable category describes `myValue`?
- [ ] A static variable.
- [ ] A stack-dynamic variable.
- [x] An explicit heap-dynamic variable.
- [ ] An implicit heap-dynamic variable.
> Study answer (implicit heap-dynamic was marked wrong). Storage is allocated and freed by **explicit programmer directives** (`allocate`/`deallocate`) — implicit heap-dynamic storage would be bound by assignment alone. (The `myValue[10]` access is a distractor about range checking.)

### ch05-q8 | fill | Practice
Using **static** scoping, what is printed?
```
var x = 1
sub A() { var x = 2; call B() }
sub B() { print x }
call A()
```
= 1
> B's static parent is the main program, so x refers to the global x = 1.

### ch05-q9 | fill | Practice
Using **dynamic** scoping, what is printed by the same program?
```
var x = 1
sub A() { var x = 2; call B() }
sub B() { print x }
call A()
```
= 2
> Dynamic scope searches the call chain: B was called by A, whose x = 2.

### ch05-q12 | mcq | 2025 Exam Q8
Which statement about accessing and modifying global variables in PHP, Python and C is most correct?
- [x] PHP's approach is less writable than both Python and C.
- [ ] PHP's approach is less reliable than both Python and C.
- [ ] PHP's approach is less readable than both Python and C.
- [ ] PHP's approach has a lower cost of execution than both Python and C.
> Study answer. In PHP a global isn't even visible in a function unless declared `global` or accessed via `$GLOBALS` — more to write than Python (read freely, `global` only to assign) and C (just use it). That restriction makes PHP *more* reliable, not less.

### ch05-q13 | mcq | Practice
Why is this code legal in C++ and Java but not in C#?
```
{
  { int x; }
  int x;
}
```
- [ ] C# doesn't allow nested blocks.
- [x] In C#, a variable's scope is the whole block it's declared in, so the outer x's scope overlaps the inner declaration.
- [ ] C# requires all variables to be declared at the start of a method.
- [ ] C# doesn't allow variables named x.
> In C++/Java the outer x's scope starts at its declaration, after the inner block.
