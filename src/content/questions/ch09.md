### ch09-q1 | mcq | 2026 Exam Q20
Which implication follows directly from the fact that subprogram definitions are executable in Python?
- [ ] Subprograms can be called from any other subprogram.
- [x] Subprograms are more writable in Python than in other programming languages.
- [ ] Subprograms are more reliable in Python than in other programming languages.
- [ ] Subprograms are more efficient in Python than in other programming languages.
> Study answer ("more efficient" was marked wrong). Executable `def`s let you choose between different definitions at run time (e.g. inside an if) — flexibility = writability. It does not make them callable from anywhere (a function exists only after its def runs), and it hurts reliability rather than helping it.

### ch09-q2 | mcq | 2026 Exam Q21
Which means of data transfer can be used for pass-by-result parameters?
- [x] Only a physical value copy can be used.
- [ ] Only an access path can be transmitted.
- [ ] Either a physical copy can be used or an access path can be transmitted.
- [ ] Only a textual substitution of actual parameters for formal parameter occurrences can be used.
> Study answer (textual substitution was marked wrong — that's pass-by-name). Pass-by-result copies the formal's final value back to the actual when the subprogram returns. Transmitting an access path would let the callee change the actual during execution, which is pass-by-reference, not out mode.

```
  call C(B)
  var value = 10
  sub B() {
    print value
  }

    call in
  }

```
